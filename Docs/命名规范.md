# Worker 与 Slot 命名规范

系统统一使用以下命名：

```text
Worker ID：worker01、worker02、worker03...
Slot ID：slot01、slot02、slot03...
```

## 1. Worker 命名

Worker ID 在整个集群中必须唯一。

建议格式：

```text
worker + 两位以上数字
```

示例：

```text
worker01
worker02
worker20
```

以下三个值必须一致：

```text
Worker 配置文件名：worker01.json
配置中的 agentId：worker01
Allocator workers.json 中的 id：worker01
```

Worker 机器建议使用相同监听端口：

```json
"listenPort": 9101
```

因为物理机器 IP 不同，不同 Worker 可以使用相同端口。

## 2. Slot 命名

Slot ID 只要求在同一台 Worker 内唯一，不要求整个集群唯一。

建议格式：

```text
slot + 两位以上数字
```

每台 Worker 都使用：

```text
slot01
slot02
```

这是允许的：

```text
worker01 / slot01
worker01 / slot02
worker02 / slot01
worker02 / slot02
```

系统内部使用：

```text
(workerId, slotId)
```

作为 Slot 唯一标识，所以 `worker01/slot01` 和 `worker02/slot01` 是两个不同资源。

## 3. 每台 Worker 的标准端口

建议每台 Worker 使用相同端口布局：

| Slot | Streamer | Player | SFU |
|---|---:|---:|---:|
| `slot01` | `8001` | `801` | `9001` |
| `slot02` | `8002` | `802` | `9002` |
| `slot03` | `8003` | `803` | `9003` |

端口只需要在同一台机器内唯一。

每台 Worker 使用相同的 Gateway 端口 `9300`。Gateway 从本 Worker 配置中的 `playerPort` 自动生成 Slot 白名单，不需要在 Gateway 配置中重复 Slot 名称。

## 4. 标准 Worker 配置

`worker01.json`：

```json
{
  "agentId": "worker01",
  "listenPort": 9101,
  "slots": [
    {
      "id": "slot01",
      "streamerPort": 8001,
      "playerPort": 801,
      "sfuPort": 9001,
      "publicUrl": "http://192.168.1.188:801/"
    },
    {
      "id": "slot02",
      "streamerPort": 8002,
      "playerPort": 802,
      "sfuPort": 9002,
      "publicUrl": "http://192.168.1.188:802/"
    }
  ]
}
```

`worker02.json`：

```json
{
  "agentId": "worker02",
  "listenPort": 9101,
  "slots": [
    {
      "id": "slot01",
      "streamerPort": 8001,
      "playerPort": 801,
      "sfuPort": 9001,
      "publicUrl": "http://192.168.1.189:801/"
    },
    {
      "id": "slot02",
      "streamerPort": 8002,
      "playerPort": 802,
      "sfuPort": 9002,
      "publicUrl": "http://192.168.1.189:802/"
    }
  ]
}
```

## 5. Allocator Worker 清单

`Allocator/config/workers.json`：

```json
{
  "workers": [
    {
      "id": "worker01",
      "baseUrl": "http://192.168.1.188:9101",
      "gatewayUrl": "http://192.168.1.188:9300",
      "token": "worker01-token"
    },
    {
      "id": "worker02",
      "baseUrl": "http://192.168.1.189:9101",
      "gatewayUrl": "http://192.168.1.189:9300",
      "token": "worker02-token"
    }
  ]
}
```

`id` 必须与对应 Worker 配置中的 `agentId` 一致。

## 6. API 和日志标识

客户端或运维人员不能只看 `slot01` 判断机器。

应同时使用：

```text
worker01 / slot01
```

Session 响应包含：

```json
{
  "workerId": "worker01",
  "slotId": "slot01"
}
```

日志目录：

```text
Worker/logs/worker01/slot01/
Worker/logs/worker01/slot02/
Worker/logs/worker02/slot01/
```

## 7. 本地停止命令

因为停止脚本在当前 Worker 机器执行，可以只写 Slot：

```bat
stop-slot.bat slot01
```

在 `worker01` 上，它停止 `worker01/slot01`。

在 `worker02` 上，它停止 `worker02/slot01`。

远程或驾驶舱界面必须同时显示 Worker 和 Slot。

## 8. 命名约束

- Worker ID 使用小写。
- Slot ID 使用小写。
- 推荐只使用字母和数字，不加入 IP、端口、横线或机器描述。
- Worker ID 全局唯一。
- Slot ID 在每个 Worker 内唯一。
- Worker 配置文件名应与 `agentId` 一致。
- 不要用端口拼接 Slot 名称，例如 `slot-8001`。
- 不要用 `W01-1` 这类同时包含 Worker 和 Slot 的旧格式。

## 9. 旧名称迁移

旧名称按以下方式转换：

| 旧值 | 新值 |
|---|---|
| `worker-01` | `worker01` |
| `worker-02` | `worker02` |
| `W01-1` | `slot01` |
| `W01-2` | `slot02` |
| `W02-1` | `slot01` |
| `W02-2` | `slot02` |

正在运行的 Slot 不能热改名。需要：

1. 停止对应 Slot 或 Worker。
2. 更新 Worker 配置和 Allocator Worker 清单。
3. 重启 Worker Agent 和 Allocator。
4. 客户端重新申请 Session。

旧 Session 会因 Allocator 重启而失效，客户端需要使用新 Session。
