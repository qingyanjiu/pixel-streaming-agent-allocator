# Pixel Streaming 配置项完整说明

本文逐个说明运行配置文件的字段、含义、必填要求和修改风险。

以下路径均相对于项目根目录。

## 1. 为什么注释写在文档里

项目运行配置使用标准 JSON：

```text
Allocator\allocator.json
Allocator\config\workers.json
Worker\worker*.json
Gateway\gateway.json
WebServers\SignallingWebServer\config.json
secrets\gateway-token.txt
```

JSON 不支持 `//` 或 `#` 注释，加入注释会导致程序无法解析。因此配置文件保持纯 JSON，所有字段说明集中写在本文件中。

`allocator.example.json`、`workers.example.json`、`worker-template.json`、`gateway.example.json` 与对应实际配置结构相同，字段含义也相同。

## 2. 当前部署地址示例

| 角色 | 示例地址 | 注意事项 |
|---|---|---|
| Allocator | `192.168.1.96:9200` | 中央调度服务；Gateway 的 `allocatorUrl` 必须指向这里 |
| Worker01 | `192.168.1.188:9101` | Worker Agent 管理接口 |
| Worker01 Gateway | `192.168.1.188:9300` | 客户端实际访问的播放器入口 |
| Worker02 | `192.168.1.189:9101` | Worker02 在线后才能被调度 |
| Worker02 Gateway | `192.168.1.189:9300` | Worker02 的播放器入口 |

IP 地址不是固定协议，部署到新网络时必须全部重新核对。

## 3. Allocator 配置

配置文件：

```text
Allocator\allocator.json
```

### 3.1 完整字段说明

| 字段 | 必填 | 含义 | 风险或建议 |
|---|---|---|---|
| `listenHost` | 是 | Allocator 监听地址 | `0.0.0.0` 表示允许其他机器访问；只允许本机时使用 `127.0.0.1` |
| `listenPort` | 是 | Allocator HTTP 端口 | 默认 `9200`；客户端和 Gateway 通过该端口访问 |
| `nodeExecutable` | 建议 | 启动器查找 Node.js 的名称或路径 | `node.exe` 表示使用 PATH；也可以填写固定路径 |
| `apiKey` | 是 | 客户端访问 Allocator 的 Client API Key | 必须替换占位值；不能与 Worker/Gateway Token 混用 |
| `apiKeyEnv` | 否 | 从环境变量读取 Client API Key | 设置后优先于 `apiKey` |
| `gatewayTokenFile` | 使用 Gateway 时必填 | Gateway 调用 Allocator 校验 Ticket 的共享 Token 文件 | 相对路径基于 `allocator.json` 所在目录 |
| `gatewayToken` | 使用 Gateway 时可替代文件 | 直接填写 Gateway Token | 不推荐在公开仓库中使用；优先使用文件或环境变量 |
| `gatewayTokenEnv` | 否 | 从环境变量读取 Gateway Token | 优先级高于 Token 文件和明文值 |
| `pollIntervalMs` | 是 | Allocator 查询 Worker 状态的间隔 | 默认 `2000`；越小越及时，但网络和 CPU 开销更高 |
| `workerRequestTimeoutMs` | 是 | 普通 Worker API 请求超时 | 默认 `5000` 毫秒 |
| `workerStartTimeoutMs` | 是 | 等待 Slot 启动完成的最长时间 | 默认 `210000` 毫秒，应大于 UE 启动时间 |
| `workerStopTimeoutMs` | 是 | 等待 Worker 停止 Slot 的最长时间 | 默认 `30000` 毫秒 |
| `idleReleaseMs` | 是 | 统一的空闲关闭时间 | 默认 `600000` 毫秒；在线确认会刷新，断线后不再刷新 |
| `autoStart` | 是 | 无空闲热实例时是否自动冷启动 | `true` 允许按需启动；`false` 只使用已运行实例 |
| `stopOnRelease` | 是 | Session 释放时是否停止 Slot | 在线程回收和断线超时后通常应保持 `true` |
| `sessionRetentionMs` | 是 | 已结束 Session 记录在内存中的保留时间 | 默认 `3600000` 毫秒；只影响历史记录，不影响活跃 Session |
| `dashboardEnabled` | 是 | 是否提供 `/dashboard/` 驾驶舱 | 生产环境可关闭，或限制 `9200` 的网络访问 |
| `dashboardDirectory` | 是 | 驾驶舱静态文件目录 | 默认 `www`，相对于 `Allocator` 源码目录 |
| `corsAllowedOrigins` | 是 | 允许直接调用 Allocator API 的浏览器来源 | `"*"` 不适合正式公网；应填写真实业务域名 |
| `workersFile` | 是 | Worker 清单文件路径 | 相对路径基于 `allocator.json` 所在目录 |

### 3.2 Allocator 的默认与替代字段

`allocator.json` 使用共享文件：

```json
{
  "gatewayTokenFile": "../secrets/gateway-token.txt"
}
```

`allocator.example.json` 演示直接值：

```json
{
  "gatewayToken": "replace-with-a-long-random-gateway-token"
}
```

二者选一种即可。Token 来源优先级：

```text
gatewayTokenEnv
  -> gatewayTokenFile
  -> gatewayToken
```

### 3.3 统一空闲关闭时间

`idleReleaseMs` 同时用于：

1. 分配后等待首次连接。
2. 玩家在线期间的空闲截止时间。
3. 玩家断开后的重连窗口。

在线玩家持续被确认时，截止时间不断刷新。断开后不再刷新，剩余时间归零才释放 Session 并停止 Slot。

### 3.4 必须重点检查的字段

- `listenHost`
- `listenPort`
- `apiKey`
- `gatewayTokenFile`
- `idleReleaseMs`
- `workersFile`
- `corsAllowedOrigins`

## 4. Worker 清单配置

配置文件：

```text
Allocator\config\workers.json
```

此文件位于中央 Allocator 机器，不在每台 Worker 上生效。

### 4.1 顶层字段

| 字段 | 必填 | 含义 |
|---|---|---|
| `workers` | 是 | Worker 对象数组；至少包含一项 |

### 4.2 每个 Worker 的字段

| 字段 | 必填 | 含义 | 风险或建议 |
|---|---|---|---|
| `id` | 是 | Worker 全局唯一 ID，例如 `worker01` | 必须与 Worker 配置的 `agentId` 完全一致 |
| `baseUrl` | 是 | Allocator 访问 Worker Agent 的地址 | 协议、IP 和 `9101` 端口必须正确，且每个 Worker 唯一 |
| `gatewayUrl` | 使用 Gateway 时必填 | 客户端访问该 Worker 的 Gateway 地址 | IP 使用 Worker 对外 IP，端口通常为 `9300` |
| `token` | 是 | Allocator 访问该 Worker 的 Token | 必须与 Worker 配置的 `authToken` 相同 |
| `tokenEnv` | 否 | 从环境变量读取 Worker Token | 优先于 `token` |

一致性要求：

```text
workers.json[id].id
  == Worker/<worker>.json[agentId]

workers.json[id].token
  == Worker/<worker>.json[authToken]
```

如果配置了任意一个 `gatewayUrl`，所有 Worker 都必须配置 Gateway。

### 4.3 IP 和端口检查

```text
baseUrl     = 从 Allocator 能访问的 Worker 管理地址 + 9101
gatewayUrl  = 从客户端能访问的 Worker 地址 + 9300
```

不要在这里填写 `127.0.0.1`，除非 Allocator 和该 Worker 确实运行在同一台机器。

## 5. Worker Agent 配置

实际配置示例：

```text
Worker\worker01.json
```

模板：

```text
Worker\worker-template.json
```

每台 Worker 只加载自己的配置文件。

### 5.1 顶层字段

| 字段 | 必填 | 含义 | 风险或建议 |
|---|---|---|---|
| `agentId` | 是 | Worker 全局唯一 ID | 必须等于 Allocator `workers.json` 中的 `id` |
| `listenHost` | 建议 | Agent 管理接口监听地址 | 省略时默认 `0.0.0.0` |
| `listenPort` | 是 | Agent 管理端口 | 默认 `9101`；不能和任何 Slot 端口冲突 |
| `authToken` | 生产必填 | Worker 管理接口 Token | 与 Allocator 中该 Worker 的 `token` 一致；空值会关闭管理认证 |
| `authTokenEnv` | 否 | 从环境变量读取 Worker Token | 优先于 `authToken` |
| `allowedAllocatorIps` | 建议 | 允许访问 Worker 管理接口的 Allocator IP 数组 | 空数组表示不限制；配置后只允许指定中央 Allocator 和本机运维地址 |
| `windowsDirectory` | 部署必填 | UE 游戏构建目录 | 未配置时退回配置文件目录；生产环境应显式配置 |
| `webServersDirectory` | 部署必填 | WebServers 根目录 | 未配置时退回配置文件目录；建议显式配置 |
| `nodeExecutable` | 否 | 启动 Wilbur 的 Node.js | 未配置时使用当前 Agent 的 Node.js；相对路径基于 `webServersDirectory` |
| `signallingDirectory` | 否 | Wilbur 源码/构建目录 | 默认 `SignallingWebServer`，相对 `webServersDirectory` |
| `gameExecutable` | 否 | UE 可执行文件名 | 默认 `UE_ANDA.exe`，相对 `windowsDirectory`；驾驶舱按该文件的进程名扫描 UE 进程 |
| `gameWorkingDirectory` | 否 | UE 进程工作目录 | 默认 `windowsDirectory` |
| `logsDirectory` | 否 | Worker 和 Slot 日志目录 | 默认 `logs`，相对 Worker Agent 源码目录 |
| `localHost` | 否 | Agent 访问本机 Wilbur 的地址 | 默认 `127.0.0.1`；不能指向远端机器 |
| `startupTimeoutMs` | 否 | 等待 UE streamer 就绪的超时 | 默认 `180000` 毫秒 |
| `serverTimeoutMs` | 否 | 等待 Wilbur REST API 就绪的超时 | 默认 `30000` 毫秒 |
| `stopTimeoutMs` | 否 | 强制停止进程前的等待时间 | 默认 `15000` 毫秒 |
| `peerOptionsFile` | 否 | WebRTC/TURN 等 peer options JSON 文件 | 相对路径基于 Worker 配置文件目录；空字符串表示不加载 |
| `maxPlayers` | 否 | Slot 未单独配置时的默认观看人数 | 默认 `1`；大于 `1` 会共享同一 UE |
| `wilburExtraArgs` | 否 | 追加给所有 Wilbur 进程的参数数组 | 参数用独立字符串；支持 `${slotId}`、`${streamerPort}`、`${playerPort}`、`${sfuPort}` |
| `ueArgs` | 否 | 追加给所有 UE 进程的启动参数 | 不能放与实际 Slot 端口冲突的参数 |
| `projectName` | 否 | 可用于 `wilburExtraArgs` 的项目名 | 不配置时参数占位符展开为空 |
| `slots` | 是 | Slot 数组 | 至少一个；每个 Slot 对应独立 Wilbur 和 UE 进程 |

### 5.2 每个 Slot 的字段

| 字段 | 必填 | 含义 | 风险或建议 |
|---|---|---|---|
| `id` | 是 | Slot ID，例如 `slot01` | 同一 Worker 内唯一；不同 Worker 可以重复 |
| `streamerPort` | 是 | UE 推流信令端口 | 例如 `8001`；同一 Agent 内不能重复 |
| `playerPort` | 是 | Wilbur 播放器和 WebSocket 端口 | 例如 `801`；同一 Agent 内不能重复 |
| `sfuPort` | 是 | Wilbur SFU 预留端口 | 例如 `9001`；当前按需分配未启用 SFU |
| `publicUrl` | 是 | 兼容直连模式的播放器地址 | 当前 Worker 校验要求必填；启用 Gateway 后客户端通常不直接访问 |
| `maxPlayers` | 否 | 当前 Slot 的最大 Player 数 | 覆盖 Worker 顶层 `maxPlayers` |
| `wilburArgs` | 否 | 只追加给当前 Slot 的 Wilbur 参数 | 支持端口和 Slot ID 占位符 |
| `ueArgs` | 否 | 只追加给当前 Slot 的 UE 参数 | 常用于覆盖分辨率、画质和实例专属参数 |

端口约束：

```text
listenPort、所有 streamerPort、playerPort、sfuPort
在同一个 Worker 配置中必须全部唯一。
```

同一个 UE 可执行文件可以启动多个进程，但每个进程必须使用不同端口。

### 5.3 UE 启停参数逐项说明

| 参数 | 含义 | 注意事项 |
|---|---|---|
| `-ExecCmds=r.RayTracing.Culling ...` | 设置光线追踪裁剪参数 | 参数内容由具体 UE 项目决定 |
| `-RenderOffScreen` | 无前台窗口渲染 | 需要显卡和桌面会话允许离屏渲染 |
| `-windowed` | 使用窗口模式 | 部分构建必须使用窗口化启动 |
| `-ForceRes` | 强制应用配置的分辨率 | 与 `-ResX/-ResY` 配合 |
| `-Unattended` | 非交互运行 | 避免弹窗阻塞自动启动 |
| `-NoSplash` | 不显示启动画面 | 常规无界面部署建议保留 |
| `-NoVerifyGC` | 跳过部分 GC 验证 | 会降低启动开销，不代表关闭 GC |
| `-NoVSync` | 关闭垂直同步 | 降低渲染等待，可能增加 GPU 占用 |
| `-AllowPixelStreamingCommands` | 允许基于 Pixel Streaming 的控制命令 | 有安全和误操作风险，只应开放给受控客户端 |
| `-PixelStreamingWebRTCFps=30` | WebRTC 目标帧率 | 高帧率会增加 GPU 和带宽 |
| `-PixelStreamingWebRTCMaxFps=30` | WebRTC 最大帧率 | 应与目标帧率协调 |
| `-PixelStreamingWebRTCMinBitrate=100000000` | 最小码率，单位 bps | 当前约 100 Mbps，配置很高 |
| `-PixelStreamingWebRTCMaxBitrate=100000000` | 最大码率，单位 bps | 局域网可高，公网必须结合上行带宽评估 |
| `-PixelStreamingEncoderMinQP=28` | H.264 最小 QP | 数值越低画质越高、带宽越大 |
| `-PixelStreamingEncoderMaxQP=30` | H.264 最大 QP | 限制画质下限；需要按项目调节 |
| `-PixelStreamingEncoderRateControl=CBR` | 使用固定码率控制 | 带宽稳定但可能浪费空闲画面带宽 |
| `-PixelStreamingEncoderKeyFrameInterval=60` | 关键帧间隔 | 影响首帧和恢复速度 |
| `-PixelStreamingWebRTCDisableReceiveAudio` | 禁用 UE 接收客户端音频 | 需要麦克风输入时必须删掉 |
| `-SILENT` | 尽量减少启动提示和声音 | 不保证关闭所有 UE 对话框 |
| `-PixelStreamingURL=ws://...` | 指向本机 Wilbur 推流端口 | 由 Worker 自动生成，不要手写 |
| `-ResX=1280` | 渲染宽度 | 每个 Slot 可覆盖 |
| `-ResY=720` | 渲染高度 | 每个 Slot 可覆盖 |

参数位置：

```text
顶层 ueArgs           = 所有 Slot 共用
Slot 内 ueArgs         = 当前 Slot 追加
最终参数               = 顶层 ueArgs + 自动 PixelStreamingURL + Slot ueArgs
```

如果同名参数重复，最终行为取决于 UE 参数解析规则，应避免冲突。

### 5.4 Worker 路径解析规则

| 路径字段 | 相对位置 |
|---|---|
| `windowsDirectory` | Worker 配置文件目录 |
| `webServersDirectory` | Worker 配置文件目录 |
| `nodeExecutable` | `webServersDirectory` |
| `signallingDirectory` | `webServersDirectory` |
| `gameExecutable` | `windowsDirectory` |
| `gameWorkingDirectory` | `windowsDirectory` |
| `logsDirectory` | Worker Agent 源码目录 |
| `peerOptionsFile` | Worker 配置文件目录 |

不要把 Windows 构建目录和 WebServers 目录强行移动成同一个目录；二者可以分别配置。

## 6. Gateway 配置

配置文件：

```text
Gateway\gateway.json
```

完整字段：

| 字段 | 必填 | 含义 | 风险或建议 |
|---|---|---|---|
| `listenHost` | 是 | Gateway 对客户端监听的地址 | `0.0.0.0` 允许远端访问 |
| `listenPort` | 是 | Gateway 播放器和 WSS 端口 | 默认 `9300`；客户端可访问 |
| `workerConfigFile` | 单独启动时必填 | Gateway 使用哪份 Worker 配置建立 Slot 白名单 | `start-worker.bat` 会用当前 Worker 配置覆盖此值 |
| `allocatorUrl` | 是 | 中央 Allocator 地址 | 必须填 Allocator 实际 IP 和 `9200`，不能误填 Worker 本机 |
| `allocatorTokenFile` | 推荐 | Bearer Gateway Token 文件 | 必须与 Allocator `gatewayTokenFile` 内容一致 |
| `allocatorToken` | 可替代文件 | 直接填写 Gateway Token | 不推荐公开明文；环境变量优先 |
| `allocatorTokenEnv` | 否 | 从环境变量读取 Gateway Token | 优先级最高 |
| `upstreamHost` | 是 | 本机 Wilbur 地址 | 只允许回环地址，不能填写远端机器 |
| `upstreamTimeoutMs` | 是 | Gateway 到本机 Wilbur 的请求超时 | 默认 `30000` 毫秒 |
| `allocatorRequestTimeoutMs` | 是 | Gateway 校验 Ticket 的请求超时 | 默认 `5000` 毫秒 |
| `nodeExecutable` | 建议 | Gateway 启动使用的 Node.js | 相对路径基于 Gateway 配置目录 |
| `tlsKeyFile` | 可选 | HTTPS 私钥文件 | 与证书必须同时配置 |
| `tlsCertFile` | 可选 | HTTPS 证书文件 | 客户端必须信任该证书 |

启动时覆盖 Worker 配置：

```bat
Gateway\start-gateway.bat gateway.json ..\Worker\worker02.json
```

`--worker-config` 优先于 `gateway.json` 中的 `workerConfigFile`。

Gateway IP 规则：

- `listenHost=0.0.0.0`：允许其他机器通过 Worker IP 访问。
- `allocatorUrl`：中央 Allocator IP。
- `upstreamHost=127.0.0.1`：本机 Wilbur，不填远端 Worker IP。

## 7. Gateway Token 文件

文件：

```text
secrets\gateway-token.txt
```

文件只有一行：

```text
<gateway-token>
```

要求：

- Allocator 和全部 Gateway 使用完全相同的内容。
- 不要带前后空格。
- 不要发给浏览器。
- 它不是 Client API Key、Worker Token、Session Token 或 Play Ticket。
- 部署时替换仓库中的占位值。

## 8. Wilbur 配置

配置文件：

```text
WebServers\SignallingWebServer\config.json
```

Worker Agent 会通过命令行覆盖其中一部分字段。

### 8.1 字段说明

| 字段 | 含义 | Worker 是否覆盖 | 注意事项 |
|---|---|---|---|
| `log_folder` | Wilbur 日志目录 | 是 | Worker 为每个 Slot 使用独立日志目录 |
| `log_level_console` | 控制台日志级别 | 否 | 可选 `debug`、`info`、`warning`、`error` |
| `log_level_file` | 文件日志级别 | 否 | 正式环境建议 `info` |
| `streamer_port` | UE 推流端口 | 是 | 来自 Slot `streamerPort` |
| `player_port` | 播放器和 Player WebSocket 端口 | 是 | 来自 Slot `playerPort` |
| `sfu_port` | SFU 端口 | 是 | 来自 Slot `sfuPort` |
| `player_keepalive_timeout` | Player ping/pong 超时 | 否 | 默认 `30000` 毫秒；断网检测依赖它 |
| `serve` | 是否提供静态网页 | 是 | Worker 启动参数包含 `--serve` |
| `http_root` | 网页静态资源目录 | 是 | Worker 固定传 `www` |
| `homepage` | 根路径网页文件 | 否 | 默认 `player.html` |
| `https` | 是否启用 HTTPS | 否 | 没有证书时不要启用 |
| `https_port` | HTTPS 端口 | 否 | 启用 HTTPS 时生效 |
| `ssl_key_path` | TLS 私钥路径 | 否 | 默认相对 Wilbur 目录 |
| `ssl_cert_path` | TLS 证书路径 | 否 | 必须与私钥匹配 |
| `https_redirect` | HTTP 是否跳转 HTTPS | 否 | 只有启用 HTTPS 时有效 |
| `rest_api` | 是否启用 Wilbur REST API | 是 | Worker 启动参数包含 `--rest_api` |
| `cors` | 是否给 Wilbur HTTP API 开启跨域 | 否 | 客户端不直接调用 Wilbur 时通常保持 `false` |
| `cors_allowed_origins` | Wilbur 允许的跨域来源 | 否 | 仅在 `cors=true` 时使用 |
| `cors_allowed_methods` | Wilbur 允许的跨域方法 | 否 | 空值使用默认方法 |
| `cors_allowed_headers` | Wilbur 允许的跨域请求头 | 否 | 空值镜像预检请求 |
| `cors_credentials` | Wilbur 是否允许跨域凭据 | 否 | 普通播放器不需要 |
| `reverse_proxy` | 是否信任代理请求头 | 否 | 通过其他反向代理访问 Wilbur 时再启用 |
| `reverse_proxy_num_proxies` | 信任的代理层数 | 否 | 与实际代理链路一致 |
| `peer_options` | WebRTC peer options JSON 字符串 | 否 | 复杂配置建议使用 Worker `peerOptionsFile` |
| `log_config` | 启动时输出配置 | 否 | 方便排障，可能包含地址信息 |
| `stdin` | 是否读取控制台输入命令 | 否 | 服务模式通常为 `false` |
| `console_messages` | 信令消息控制台详细程度 | 否 | `verbose` 日志较多 |

### 8.2 心跳与断线

当前关键值：

```text
player_keepalive_timeout = 30000
```

行为：

```text
Wilbur 每 30 秒发送 ping
浏览器返回 pong
连续没有 pong 时 Wilbur 终止失效 WebSocket
Allocator 每 2 秒从 Worker 读取 playerCount
在线时刷新 idleReleaseMs
断开后不再刷新，10 分钟后停止 Slot
```

## 9. 高风险配置总表

### 9.1 ID 必须一致

| 配置 A | 配置 B |
|---|---|
| `Worker.agentId` | `workers.json.workers[].id` |
| `Worker.authToken` | `workers.json.workers[].token` |
| Slot `id` | 同一 Worker 内唯一，推荐 `slot01`、`slot02` |
| Gateway 实际加载的 Worker 配置 | 必须与 `gatewayUrl` 对应同一台机器 |

### 9.2 Token 必须一致

```text
Worker.authToken
  == workers.json.token

Allocator.gatewayTokenFile
  == Gateway.allocatorTokenFile
```

### 9.3 Allocator 归属必须明确

建议每台 Worker 只允许中央 Allocator IP：

```json
{
  "allowedAllocatorIps": [
    "192.168.1.96",
    "127.0.0.1",
    "::1"
  ]
}
```

`127.0.0.1` 和 `::1` 用于本机 `stop-slot.bat`、`stop-all-slots.bat` 等运维脚本。不要把另一台 Allocator 的地址加入同一 Worker 的白名单，否则两个 Allocator 可能同时管理同一个 Slot。

### 9.4 IP 必须区分

| 配置 | 填写哪台机器 |
|---|---|
| `workers.json.baseUrl` | Worker IP |
| `workers.json.gatewayUrl` | Worker IP |
| `Gateway.allocatorUrl` | 中央 Allocator IP |
| `Worker.localHost` | 本机回环 `127.0.0.1` |
| `Gateway.upstreamHost` | 本机回环 `127.0.0.1` |

### 9.5 端口统一规划

| 端口 | 用途 |
|---:|---|
| `9200` | Allocator |
| `9101` | Worker Agent |
| `9300` | Gateway |
| `8001/8002/...` | UE 到 Wilbur 推流 |
| `801/802/...` | Wilbur 播放器和 WebSocket，本机 Gateway 使用 |
| `9001/9002/...` | Wilbur SFU 预留 |
| `443` | 可选 Gateway HTTPS |

### 9.6 路径必须存在

- `gameExecutable`
- `webServersDirectory`
- `signallingDirectory/dist/index.js`
- `nodeExecutable`
- `www/player.html`
- `gatewayTokenFile`

## 10. 修改配置后的检查顺序

1. 校验 JSON 格式。
2. 检查 Worker ID 和 Token 对应关系。
3. 检查 Allocator、Worker、Gateway IP。
4. 检查端口是否冲突。
5. 检查路径在对应机器上是否存在。
6. 检查 Gateway Token 内容一致。
7. 启动 Allocator。
8. 启动 Worker 和 Gateway。
9. 检查三个健康接口。
10. 申请一个测试 Session，确认播放器和 WebSocket。

PowerShell 检查 JSON：

```powershell
Get-Content -Raw Allocator\allocator.json | ConvertFrom-Json
Get-Content -Raw Allocator\config\workers.json | ConvertFrom-Json
Get-Content -Raw Worker\worker01.json | ConvertFrom-Json
Get-Content -Raw Gateway\gateway.json | ConvertFrom-Json
Get-Content -Raw WebServers\SignallingWebServer\config.json | ConvertFrom-Json
```

健康检查：

```text
http://Allocator-IP:9200/health
http://Worker-IP:9101/health
http://Worker-IP:9300/health
```

## 11. 常见配置错误

### Gateway 报 `fetch_failed`

检查 `Gateway/gateway.json`：

```json
"allocatorUrl": "http://<实际AllocatorIP>:9200"
```

不要指向 Gateway 自己，除非 Allocator 确实运行在同一台机器。

### Gateway 返回 401

检查 Allocator 和 Gateway 是否读取同一份 Gateway Token。

### Allocator 显示 Worker 离线

检查：

```text
workers.json.baseUrl
Worker.listenHost
Worker.listenPort
Worker.authToken
Windows 防火墙
```

### Worker 显示开始失败

检查：

```text
windowsDirectory
webServersDirectory
gameExecutable
nodeExecutable
signallingDirectory
端口占用
GPU资源
```

### 能打开本地 801 但 Gateway 403

说明 Allocator、Gateway Token 或 Session Ticket 有问题，不是 Wilbur 页面问题。
