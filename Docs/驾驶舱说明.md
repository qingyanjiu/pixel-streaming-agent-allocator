# Pixel Streaming 流资源驾驶舱

Allocator 内置只读驾驶舱，用简单状态展示当前有多少线路可用、多少用户正在使用，以及是否有服务异常。

## 1. 访问

启动 Allocator 后打开：

```text
http://Allocator-IP:9200/dashboard/
```

访问 `/` 或 `/dashboard` 会自动跳转到驾驶舱。

页面会要求输入 [allocator.json](../Allocator/allocator.json) 中的 `apiKey`。

密钥只保存在当前浏览器标签页的 `sessionStorage`，不会写入 HTML、JavaScript 或 Git。

如果当前标签页已经保存了 Key，刷新页面时只显示“正在验证已保存的会话”，验证成功后直接进入资源统计页，不会先闪现登录页。只有没有 Key 或服务返回 `401` 时才显示登录表单。

## 2. 页面结构

### 顶部实时状态

- Allocator 数据是否同步成功
- 当前时间
- 手动刷新
- 清除 API Key 并锁定页面

### 资源总览

- 总资源数：当前登记的全部线路。
- 可用：没有预约、当前没有用户连接，并且资源没有异常的线路；通常就是尚未启动的线路。
- 已连接：当前已经有用户连接的线路数，说明中同时显示用户人数。
- 已预约：已经分配给客户，但当前还没有用户连接的线路。
- 正常比例：未处于异常或离线状态的线路比例。

### 服务器

- 服务器名称
- 在线/离线
- 可用线路数
- 当前用户数
- 最近响应时间
- 离线错误

### 线路明细

- 线路名称
- 所在服务器
- 状态
- 当前用户数
- 简单说明，例如“可以接受新用户”“用户正在使用”“有新请求时自动启动”

支持：

- 按全部、可用、使用中、已预约、需要关注筛选
- 按服务器筛选
- 按线路名称或服务器名称搜索
- 每 3 秒自动刷新
- 页面隐藏时暂停自动刷新

端口、PID、Session ID 等技术信息不再显示在默认驾驶舱页面中。排障时使用 Allocator API 和 Worker 日志。

### 已预约客户

列表展示所有已经分配、但当前没有玩家连接的线路：

- Worker 和 Slot 名称。
- 发起预约的客户端 IP。
- 当前预约状态。
- 距离自动释放的剩余时间。
- `释放并停止` 按钮。

点击按钮后会：

1. 立即结束对应 Session。
2. 释放 Slot 租约。
3. 停止该 Slot 的 UE 和 Wilbur。
4. 刷新驾驶舱。

即使 Allocator 配置了 `stopOnRelease=false`，驾驶舱的“释放并停止”仍然会强制停止对应 Slot。

## 3. 数据来源

驾驶舱通过同源接口读取：

```http
GET /api/slots
X-API-Key: <apiKey>
```

接口会实时查询 Worker Agent。某个 Worker 无法访问时，页面会继续显示其他 Worker，并标记离线节点。

每个已被租用的 Slot 会额外返回不含 Session Token 的 `lease` 信息：

```json
{
  "sessionId": "...",
  "status": "ready",
  "clientAddress": "192.168.1.150",
  "deadline": "2026-10-30T10:10:00.000Z"
}
```

释放并停止接口：

```http
POST /api/slots/{workerId}/{slotId}/release
X-API-Key: <apiKey>
Content-Type: application/json

{}
```

## 4. 配置

在 [allocator.json](../Allocator/allocator.json) 中：

```json
{
  "dashboardEnabled": true,
  "dashboardDirectory": "www"
}
```

`dashboardDirectory` 相对于 `Allocator` 目录。

如果不需要驾驶舱：

```json
"dashboardEnabled": false
```

修改配置后需要重启 Allocator。

## 5. 安全

- 驾驶舱 HTML/CSS/JavaScript 是只读静态资源。
- 统计数据仍需要 Client API Key。
- API Key 不进入 URL，也不写入服务器日志。
- 页面不可被 iframe 嵌入。
- 页面使用内容安全策略，只加载 Allocator 自身资源。
- 建议只将 `9200` 开放给运维网络。

## 6. 调试

### 页面一直要求输入 Key

确认输入的是：

```text
Allocator/allocator.json -> apiKey
```

不是 Worker Token，也不是 Session Token。

### Worker 显示离线

驾驶舱会显示 Worker 的 `lastError`。继续检查：

- Allocator 到 Worker 的 `9101`。
- Worker Token 是否一致。
- Worker Agent 是否运行。

### 服务器在线但线路未启动

查看线路状态和错误信息，再查看：

```text
Worker/logs/<agentId>/<slotId>/wilbur.log
Worker/logs/<agentId>/<slotId>/ue.log
```
