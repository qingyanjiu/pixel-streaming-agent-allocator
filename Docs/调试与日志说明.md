# 调试与日志说明

Allocator、Worker Agent 和 Gateway 会在各自的控制台打印客户端申请、Slot 分配、实例启动、Ticket 校验和 Player 连接状态，便于区分请求是否到达、实例是否启动、是否经过 Gateway，以及客户端是否真正连上。

浏览器可视化资源状态见 [流资源驾驶舱说明](驾驶舱说明.md)。

## 1. Allocator 控制台

启动：

```bat
Allocator\start-allocator.bat
```

客户端申请时会打印类似：

```text
[allocator] 2026-10-28T01:20:00.000Z event=client_session_request client=::ffff:192.168.1.150 origin=http://localhost:3000
[allocator] 2026-10-28T01:20:00.005Z event=session_created session=... client=::ffff:192.168.1.150
[allocator] 2026-10-28T01:20:00.010Z event=slot_assigned session=... client=::ffff:192.168.1.150 worker=worker01 slot=slot01 mode=cold
[allocator] 2026-10-28T01:20:00.012Z event=session_status session=... from=allocating to=starting client=::ffff:192.168.1.150 worker=worker01 slot=slot01
```

Worker 和 Wilbur 就绪后：

```text
[allocator] event=session_status ... from=starting to=ready ... reason=slot_ready
```

Player 连接后：

```text
[allocator] event=session_status ... from=ready to=active ... reason=player_connected
```

Player 断开后：

```text
[allocator] event=session_status ... from=active to=disconnected ... reason=player_disconnected
[allocator] event=reconnect_window_started session=... deadline=2026-10-28T01:30:00.000Z
```

10 分钟内重连：

```text
[allocator] event=session_status ... from=disconnected to=active ... reason=player_reconnected
[allocator] event=session_reconnected session=... client=... worker=... slot=...
```

释放或超时：

```text
[allocator] event=session_status ... to=released ... reason=client_requested
```

手动停止 Slot 后，下一次轮询会记录：

```text
[allocator] event=session_status ... to=released ... reason=worker_stopped
```

UE 或 Wilbur 异常退出会记录：

```text
[allocator] event=session_status ... to=released ... reason=worker_failed
```

Allocator 还会打印 Worker 上下线：

```text
[allocator] event=worker_online worker=worker01 address=http://192.168.1.188:9101 slots=2
[allocator] event=worker_offline worker=worker01 address=http://192.168.1.188:9101
```

普通 Session 轮询查询不会打印日志，避免每秒刷屏；只有关键状态变化会输出。

## 2. Worker 控制台

启动：

```bat
Worker\start-worker.bat worker01.json
```

该脚本会在独立窗口启动 Gateway。主窗口显示 Worker 日志，Gateway 窗口显示 Ticket 和 WebSocket 日志。

Allocator 请求启动 Slot：

```text
[worker] event=slot_start_request worker=worker01 slot=slot01 client=::ffff:192.168.1.10
[worker] event=slot_starting worker=worker01 slot=slot01 streamerPort=8001 playerPort=801
[worker] event=wilbur_starting worker=worker01 slot=slot01
[worker] event=wilbur_ready worker=worker01 slot=slot01 pid=1234
[worker] event=ue_starting worker=worker01 slot=slot01 executable=...
[worker] event=ue_process_started worker=worker01 slot=slot01 pid=5678
[worker] event=streamer_ready worker=worker01 slot=slot01 streamers=1
[worker] event=slot_ready worker=worker01 slot=slot01
```

浏览器连接 Wilbur 后：

```text
[worker] event=player_connected worker=worker01 slot=slot01 previousPlayers=0 players=1
[worker] event=wilbur_event worker=worker01 slot=slot01 message="... New player connection: ::ffff:192.168.1.150 (/)"
```

浏览器断开：

```text
[worker] event=player_disconnected worker=worker01 slot=slot01 previousPlayers=1 players=0
[worker] event=wilbur_event worker=worker01 slot=slot01 message="... Player Player0 (...) disconnected."
```

Slot 停止：

```text
[worker] event=slot_stop_request worker=worker01 slot=slot01 client=...
[worker] event=slot_stopping worker=worker01 slot=slot01
[worker] event=slot_stopped worker=worker01 slot=slot01
```

手动停止单个 Slot：

```bat
Worker\stop-slot.bat slot01
```

手动停止当前 Worker 的全部 Slot：

```bat
Worker\stop-all-slots.bat
```

这两个 BAT 会调用 Worker Agent 的受保护停止接口，读取配置中的 Token，并且只停止对应机器上的 Slot。

## 3. Gateway 控制台

启动：

```bat
Gateway\start-gateway.bat
```

正常打开播放器：

```text
[gateway] event=http_request client=::ffff:192.168.1.150 session=... worker=worker01 slot=slot01 path=/
[gateway] event=http_request client=::ffff:192.168.1.150 session=... worker=worker01 slot=slot01 path=/player.js
[gateway] event=websocket_connected client=::ffff:192.168.1.150 session=... worker=worker01 slot=slot01 upstreamPort=801
```

Allocator 同时会打印：

```text
[allocator] event=play_ticket_validated client=... session=... worker=worker01 slot=slot01 status=ready
```

错误票据：

```text
[gateway] event=ticket_rejected client=... route=/ reason=invalid_or_inactive_session
```

Allocator 不可达：

```text
[gateway] event=allocator_validation_failed client=... route=/ error=...
```

本机 Wilbur 不可达：

```text
[gateway] event=upstream_http_failed ... slot=slot01 error=...
[gateway] event=upstream_websocket_failed ... slot=slot01 error=...
```

根目录 `stop-all.bat` 会先关闭 `workers.json` 中的全部 Gateway，再向 Worker 发送 `shutdown_request`；Worker 停止全部 Slot 后退出，最后关闭 Allocator。

直接杀掉 UE 后为什么 Wilbur 仍然存在、Session 为何暂时不能复用，见
[UE 进程与 Slot 停止说明](UE进程与Slot停止说明.md)。

## 4. 日志文件

Worker 控制台同时保留完整文件日志：

```text
Worker\logs\worker01\slot01\wilbur.log
Worker\logs\worker01\slot01\ue.log
Worker\logs\worker01\slot01\wilbur-logs\
```

实时查看：

```powershell
Get-Content `
  Worker\logs\worker01\slot01\wilbur.log `
  -Wait
```

## 5. 调试判断

### 客户端点击连接后 Allocator 没有日志

请求没有到达 Allocator，检查：

- 前端 URL 是否使用 `http://Allocator-IP:9200/api/sessions`。
- CORS 是否允许前端 Origin。
- Client API Key 是否正确。
- 浏览器 Network 面板中的实际请求。

### Allocator 有 slot_assigned，但 Worker 没有日志

检查：

- Allocator 是否能访问 Worker 的 `9101`。
- `Allocator/config/workers.json` 中地址是否正确。
- Worker 的 `authToken` 与 Allocator 的 `token` 是否一致。
- 防火墙是否放行 `9101`。

### Worker 已 slot_ready，但 Gateway 没有 websocket_connected

说明 UE 已启动，但浏览器还没有连接对应 Wilbur。检查：

- 客户端是否打开 Allocator 返回的 Gateway `url`。
- Gateway `9300` 是否可从客户端访问。
- URL 是否保留了 `ss` 查询参数。
- Gateway Token 是否与 Allocator 一致。
- HTTPS 页面是否使用 HTTPS Gateway 和 WSS。

### Gateway 已有 websocket_connected，但 Worker 没有 player_connected

检查：

- Gateway 与 Worker 是否部署在同一台机器。
- `gateway.json` 是否读取了正确的 `workerConfigFile`。
- Windows 防火墙是否允许本机回环访问 Wilbur。
- Wilbur 的 `801/802` 是否仍在监听。

### player_connected 出现后立刻 disconnected

重点检查：

- WebRTC UDP/TURN。
- 浏览器控制台 WebRTC 错误。
- Wilbur 和 UE 日志。

## 6. 安全说明

控制台日志不会输出：

- Client API Key
- Worker Token
- Session Token
- Gateway Token
- Play Ticket
- WebRTC SDP

不要把正式 Token 手动加入日志字符串。
