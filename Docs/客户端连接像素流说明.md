# 前端客户端连接 Pixel Streaming 说明

本文面向前端开发，说明如何向 Allocator 申请 UE 实例、等待冷启动、打开播放器、处理错误并释放会话。

相关文档：

- [架构说明.md](架构说明.md)
- [Gateway网关说明.md](Gateway网关说明.md)
- [认证与密钥说明.md](认证与密钥说明.md)
- [启动说明.md](启动说明.md)

## 1. 连接关系

前端不直接选择 Worker，也不直接查询 Worker Agent。

```text
业务前端
  -> Allocator :9200，申请 Session
  <- 返回某个 Worker 的 Gateway URL 和短期 Play Ticket

业务前端
  -> Gateway :9300/play/<ticket>/，打开完整 Pixel Streaming 播放器

播放器
  -> Gateway :9300/play/<ticket>/ws，建立 WebSocket 信令

Gateway
  -> 本机 Wilbur 127.0.0.1:801/802

播放器
  <-> UE，建立 WebRTC UDP 媒体连接
```

Allocator 返回的 `url` 已经包含 Ticket 和播放器需要的 `ss` 信令参数。前端直接打开该 URL 即可，不要自行拼接 `801/802` 地址，也不要移除或修改查询参数。

## 2. 浏览器和网络要求

浏览器必须能够访问：

- Allocator 的 TCP `9200`。
- 返回的 `url` 对应 Worker 的 Gateway TCP `9300`。
- Worker/UE 的 WebRTC UDP，或配置好的 TURN。

能打开播放器页面不代表视频一定可播放。黑屏和连接失败通常与 UDP、TURN 或防火墙有关。

## 3. CORS

业务前端与 Allocator 不同源时，需要修改：

```text
Allocator\allocator.json
```

配置：

```json
{
  "corsAllowedOrigins": [
    "http://localhost:3000",
    "https://app.example.com"
  ]
}
```

正式环境不建议长期使用 `["*"]`。

Allocator 已支持以下请求头的预检：

```text
Content-Type
Authorization
X-API-Key
X-Session-Token
Idempotency-Key
```

## 4. HTTPS 和 WSS

如果业务前端使用 HTTPS：

- `workers.json` 中的 `gatewayUrl` 也必须是 HTTPS。
- 播放器信令应使用 WSS。
- 不要在 HTTPS 页面嵌入 `http://WorkerIP:9300/` 或 `http://WorkerIP:801/`，否则会被当作混合内容阻止。

Allocator 根据 `gatewayUrl` 自动生成 HTTP/WS 或 HTTPS/WSS 地址，具体以返回的 `url` 协议为准。

## 5. 鉴权

如果 Allocator 配置了 `apiKey`，请求需要携带：

```http
X-API-Key: <client-api-key>
```

也可以使用：

```http
Authorization: Bearer <client-api-key>
```

不要把 Worker Token 或 Gateway Token 发给浏览器，也不要用这些内部 Token 调用 Allocator 客户端接口。

公共网站应将 Allocator 请求放在业务后端，由后端保存长期 API Key 并验证用户登录。

## 6. API

| 方法 | 路径 | 用途 |
|---|---|---|
| `POST` | `/api/sessions` | 申请一个 UE 实例 |
| `GET` | `/api/sessions/{sessionId}` | 查询状态 |
| `DELETE` | `/api/sessions/{sessionId}` | 主动释放 |

普通前端不需要使用：

```text
/slots
/api/slots
```

这些是 Worker 或 Allocator 内部管理接口。

## 7. 申请实例

```http
POST /api/sessions
X-API-Key: <client-api-key>
Idempotency-Key: <单次申请唯一ID>
Content-Type: application/json

{}
```

同一次申请因网络超时重试时，必须复用原来的 Idempotency-Key。

用户重新点击“开始新会话”时，应生成新的值，推荐：

```ts
crypto.randomUUID()
```

## 8. 响应

### 201：热实例可用

```json
{
  "sessionId": "4c82d0bf-c77c-4cb3-b37e-8f1ffe6544a8",
  "sessionToken": "temporary-session-capability-token",
  "status": "ready",
  "message": "服务已就绪，正在等待播放器连接。",
  "url": "http://192.168.1.21:801/",
  "pollUrl": "/api/sessions/4c82d0bf-c77c-4cb3-b37e-8f1ffe6544a8",
  "workerId": "worker01",
  "slotId": "slot01",
  "createdAt": "2026-10-27T09:00:00.000Z",
  "readyAt": "2026-10-27T09:00:05.000Z",
  "disconnectedAt": null,
  "reconnectDeadline": null,
  "expiresAt": "2026-10-27T09:10:05.000Z",
  "reason": null,
  "error": null
}
```

可以直接打开 `url`。

`expiresAt` 表示当前的统一空闲截止时间，不是固定的会话总寿命。玩家在线时，Allocator 每次确认连接有效都会把该时间刷新为 `当前时间 + idleReleaseMs`；断开后不再刷新。

创建 Session 的响应会返回一次 `sessionToken`。前端必须保存它；后续查询和释放都需要：

```http
X-Session-Token: <sessionToken>
```

### 202：正在冷启动

```json
{
  "sessionId": "...",
  "sessionToken": "temporary-session-capability-token",
  "status": "starting",
  "message": "正在启动 Pixel Streaming 服务，请稍候...",
  "url": null,
  "pollUrl": "/api/sessions/..."
}
```

前端需要轮询 `pollUrl`。

### 503：没有容量

```http
HTTP/1.1 503 Service Unavailable
Retry-After: 5
```

```json
{
  "error": "No free or startable Pixel Streaming slots are currently available.",
  "message": "当前没有可用的 Pixel Streaming 实例，请稍后重试。",
  "retryAfterMs": 5000
}
```

503 不占用 Idempotency-Key，客户端可以等待后使用同一个 Key 重试。

### 401：密钥错误

可能是：

- Client API Key 错误：`{"error":"unauthorized"}`。
- Session Token 缺失或错误：`{"error":"session_unauthorized"}`。

检查请求头、对应 Session 凭证以及 Allocator 重启状态。

## 9. Session 状态

| 状态 | 前端动作 |
|---|---|
| `starting` | 显示启动动画并继续轮询 |
| `ready` | 打开 `url` |
| `active` | 玩家已经连接 |
| `disconnected` | 玩家已断开，保留 Slot 等待重连 |
| `released` | 停止播放器，回到业务页 |
| `failed` | 显示失败并允许重新申请 |
| `no_capacity` | 显示容量不足 |

建议每 `1000 ms` 轮询一次。UE 冷启动可按最长 210 秒处理。

`message` 字段可以直接用于 UI：

```text
正在启动 Pixel Streaming 服务，请稍候...
服务已就绪，正在等待播放器连接。
连接已断开，可在 597 秒内重连。
```

## 9.1 断线和重连

当前配置：

```text
idleReleaseMs = 600000
player_keepalive_timeout = 30000
Worker 状态轮询 = 2000ms
```

行为：

```text
第一次等待连接超过 10 分钟
  -> 回收 Slot

玩家连接中
  -> Wilbur 每 30 秒发送 ping
  -> 浏览器返回 pong
  -> Allocator 每次确认在线都把同一个 10 分钟截止时间刷新
  -> 只要连接和心跳正常，不会因为 Session TTL 自动关闭

玩家连接后断开
  -> Session 进入 disconnected
  -> 不再刷新 10 分钟截止时间
  -> Slot 从最后一次确认在线开始保留 10 分钟
  -> 同一 Session 可以重连
  -> 10 分钟内没有重连才停止 UE 和 Wilbur
```

如果浏览器关闭、网线断开或电脑休眠而没有正常 WebSocket 关闭帧，Wilbur 的心跳检测通常会在约 30～60 秒内判定连接失活。之后 Allocator 不再刷新截止时间，并在剩余重连窗口结束后停止 Slot。

重连期间，新用户申请只能使用其他可启动 Slot。被保留的 Slot 不会分配给新用户。

该 10 分钟窗口只适用于 Slot 仍在运行、仅 Player 连接断开的场景。如果维护人员停止了 Slot，或 Worker 报告 Slot 异常终止，Session 会在下一次轮询中立即释放，不能继续用旧 Session 重连。

前端应在创建 Session 后保存：

```ts
{
  sessionId,
  sessionToken,
  url
}
```

例如可以暂存到当前标签页的 `sessionStorage`：

```ts
sessionStorage.setItem(
  "pixel-session",
  JSON.stringify({
    sessionId: session.sessionId,
    sessionToken: session.sessionToken,
    url: session.url
  })
);
```

如果 Session 需要跨标签页、跨设备或绑定登录用户，应改由业务后端保存和校验归属关系。

页面刷新或网络恢复时：

1. 读取原 `sessionId` 和 `sessionToken`。
2. 使用这两个值查询 Session。
3. 状态为 `ready`、`active` 或 `disconnected` 时继续使用原 `url`。
4. 状态为 `released` 或 `failed` 时清除旧记录并重新申请。

更严格的生产系统应由业务后端把“当前登录用户”和 Session 绑定，而不是只相信浏览器保存的客户端 ID。`sessionToken` 是不可猜测的会话凭证，业务前端不应把它打印到公开日志。

## 10. TypeScript 示例

以下示例假设前端被允许直接访问 Allocator。

```ts
type PixelSessionStatus =
  | "allocating"
  | "starting"
  | "ready"
  | "active"
  | "disconnected"
  | "released"
  | "failed"
  | "no_capacity";

interface PixelSession {
  sessionId: string;
  sessionToken?: string;
  status: PixelSessionStatus;
  message: string;
  url: string | null;
  pollUrl: string;
  workerId: string | null;
  slotId: string | null;
  createdAt: string;
  readyAt: string | null;
  disconnectedAt: string | null;
  reconnectDeadline: string | null;
  expiresAt: string;
  reason: string | null;
  error: string | null;
}

class PixelApiError extends Error {
  status: number;
  retryAfterMs?: number;

  constructor(message: string, status: number, retryAfterMs?: number) {
    super(message);
    this.name = "PixelApiError";
    this.status = status;
    this.retryAfterMs = retryAfterMs;
  }
}

const ALLOCATOR_BASE_URL = "http://192.168.1.10:9200";
const CLIENT_API_KEY = "internal-client-api-key";

async function allocatorRequest<T>(
  path: string,
  sessionToken?: string,
  init: RequestInit = {}
): Promise<T> {
  const response = await fetch(`${ALLOCATOR_BASE_URL}${path}`, {
    ...init,
    headers: {
      "Content-Type": "application/json",
      "X-API-Key": CLIENT_API_KEY,
      ...(sessionToken ? { "X-Session-Token": sessionToken } : {}),
      ...(init.headers ?? {})
    }
  });

  const body = await response.json().catch(() => ({}));
  if (!response.ok) {
    const retryAfter = Number(response.headers.get("Retry-After"));
    throw new PixelApiError(
      body.error ?? `Allocator HTTP ${response.status}`,
      response.status,
      Number.isFinite(retryAfter) && retryAfter > 0
        ? retryAfter * 1000
        : body.retryAfterMs
    );
  }
  return body as T;
}

export async function getPixelSession(
  sessionId: string,
  sessionToken: string
): Promise<PixelSession> {
  return allocatorRequest<PixelSession>(
    `/api/sessions/${encodeURIComponent(sessionId)}`,
    sessionToken
  );
}

export async function waitForPixelSession(
  initialSession: PixelSession,
  timeoutMs = 210_000,
  onStatus: (message: string) => void = () => undefined
): Promise<PixelSession> {
  let session = initialSession;
  const sessionToken = initialSession.sessionToken;
  if (!sessionToken) {
    throw new PixelApiError("缺少 Session Token", 401);
  }
  const deadline = Date.now() + timeoutMs;
  onStatus(session.message);

  while (session.status === "starting") {
    if (Date.now() >= deadline) {
      throw new PixelApiError("UE 实例启动超时", 408);
    }
    await new Promise((resolve) => setTimeout(resolve, 1000));
    const refreshed = await getPixelSession(session.sessionId, sessionToken);
    session = {
      ...refreshed,
      sessionToken
    };
    onStatus(session.message);
  }

  if (
    session.status !== "ready" &&
    session.status !== "active" &&
    session.status !== "disconnected"
  ) {
    throw new PixelApiError(
      session.error ?? `UE 分配失败：${session.status}`,
      409
    );
  }
  if (!session.url) {
    throw new PixelApiError("Allocator 没有返回播放器地址", 500);
  }
  return session;
}

export async function createPixelSession(
  idempotencyKey: string = crypto.randomUUID(),
  onStatus: (message: string) => void = () => undefined
): Promise<PixelSession> {
  const session = await allocatorRequest<PixelSession>("/api/sessions", undefined, {
    method: "POST",
    headers: {
      "Idempotency-Key": idempotencyKey
    },
    body: JSON.stringify({})
  });
  return waitForPixelSession(session, 210_000, onStatus);
}

export async function releasePixelSession(
  sessionId: string,
  sessionToken: string
): Promise<void> {
  await allocatorRequest<PixelSession>(
    `/api/sessions/${encodeURIComponent(sessionId)}`,
    sessionToken,
    { method: "DELETE" }
  );
}

export async function resumePixelSession(
  saved: { sessionId: string; sessionToken: string }
): Promise<PixelSession | null> {
  const session = await getPixelSession(saved.sessionId, saved.sessionToken);
  if (session.status === "released" || session.status === "failed") {
    return null;
  }
  return session.status === "starting"
    ? waitForPixelSession({
          ...session,
          sessionToken: saved.sessionToken
      })
    : {
          ...session,
          sessionToken: saved.sessionToken
      };
}
```

## 11. iframe 接入

业务页面有自己的框架时，推荐 iframe：

```ts
const frame = document.getElementById(
  "pixel-player"
) as HTMLIFrameElement;

frame.src = session.url;
```

```html
<iframe
  id="pixel-player"
  title="Unreal Pixel Streaming"
  allow="autoplay; fullscreen; gamepad"
  allowfullscreen
  style="width: 100%; height: 100%; border: 0"
></iframe>
```

注意：

- 需要把键盘焦点交给 iframe，UE 才能接收输入。
- 浏览器可能禁止无用户操作播放，要保留 Play 按钮。
- iframe 内是跨域页面，业务前端不能读取其内部 DOM。
- 用户结束会话时应调用 `releasePixelSession`。
- 不要因为 React 开发模式的重复挂载就无条件释放 Session。

## 12. 新窗口接入

浏览器可能拦截异步等待后的 `window.open`。应在点击事件中立即打开空白窗口：

```ts
async function startInNewWindow() {
  const popup = window.open("", "pixel-streaming");
  if (!popup) {
    throw new Error("浏览器阻止了播放器窗口");
  }

  popup.document.write("正在分配 UE 实例...");

  try {
    const session = await createPixelSession(crypto.randomUUID());
    popup.location.href = session.url!;

    const timer = window.setInterval(() => {
      if (popup.closed) {
        window.clearInterval(timer);
        void releasePixelSession(
          session.sessionId,
          session.sessionToken!
        );
      }
    }, 1000);
  } catch (error) {
    popup.close();
    throw error;
  }
}
```

## 13. 当前窗口跳转

```ts
window.location.assign(session.url!);
```

这种模式下业务页面会被替换，无法继续主动调用释放接口。

不要在跳转前通过 `pagehide` 立即 DELETE，因为跳转到播放器本身就会触发 `pagehide`，会把刚分配的实例释放掉。

跳转后用户关闭页面，Allocator 会在检测到玩家断开并超过 `idleReleaseMs` 后自动回收。

## 14. 主动退出

iframe 或业务页面仍存在时：

```ts
await releasePixelSession(session.sessionId, session.sessionToken!);
frame.src = "about:blank";
```

只在用户明确结束会话时使用 `keepalive`：

```ts
void fetch(`${ALLOCATOR_BASE_URL}/api/sessions/${session.sessionId}`, {
  method: "DELETE",
  headers: {
    "X-API-Key": CLIENT_API_KEY,
    "X-Session-Token": session.sessionToken!
  },
  keepalive: true
});
```

## 15. 后端代理

公共网站推荐：

```text
浏览器 -> 业务后端 -> Allocator
```

后端保存 `apiKey` 并校验用户登录，浏览器只接收：

```json
{
  "sessionId": "...",
  "status": "ready",
  "url": "http://WorkerIP:9300/play/<ticket>/?ss=ws%3A%2F%2FWorkerIP%3A9300%2Fplay%2F<ticket>%2Fws"
}
```

不要把 Allocator API Key 返回浏览器。

## 16. 错误处理

| HTTP 状态 | 前端处理 |
|---|---|
| `201` | 打开播放器 |
| `202` | 显示启动中，继续轮询 |
| `401` | 显示配置或登录错误 |
| `404` | Session 已回收，重新申请 |
| `503` | 显示容量不足，按 Retry-After 重试 |
| `500` | 显示服务异常 |
| 网络失败 | 提示网络异常；无法确认结果时复用原 Idempotency-Key 重试 |

## 17. 联调检查

1. `POST /api/sessions` 返回 201 或 202。
2. 202 后能轮询到 ready。
3. `url` 的路径是 `/play/<ticket>/`，且能在浏览器直接打开。
4. 没有 CORS 或混合内容错误。
5. Gateway 控制台出现 `websocket_connected`，播放器能建立 WebSocket/WSS。
6. WebRTC 能建立 UDP/TURN。
7. iframe 获得键盘焦点。
8. 退出后 Session 变为 released。
9. 直接关闭播放器后能自动回收。
10. 多个用户被分配到不同 Slot。
11. Session 释放后重复打开旧 `url` 返回 `403`。
12. 客户端不能直接访问远端 `801/802`。

## 18. 禁止事项

- 不由前端轮流查询各 Worker Agent。
- 不向前端发送 Worker Token。
- 不把 Worker Token 放入 URL。
- 不丢失创建响应中的 `sessionToken`。
- 不让多个客户端自行抢占 Slot。
- 不在 iframe 每次重新挂载时无条件释放 Session。
- 不在页面跳转的 `pagehide` 中释放刚创建的 Session。
- 不把 Allocator API Key 写入公开仓库或浏览器日志。
