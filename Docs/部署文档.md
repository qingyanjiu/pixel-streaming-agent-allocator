# Pixel Streaming 完整部署文档

本文从空白机器开始，说明 Allocator、Worker Agent、Gateway、Wilbur 和 UE 游戏构建的部署、配置、启动、健康检查和升级。

除特别说明外，路径都相对于项目根目录。

## 1. 部署拓扑

推荐使用：

```text
1 台中央 Allocator 机器
N 台 GPU Worker 机器
```

每台 Worker 机器同时运行：

```text
Worker Agent + Gateway + Wilbur + UE
```

整体访问关系：

```text
客户端
  -> Allocator :9200，申请 Session
  <- Gateway URL
  -> Worker Gateway :9300，加载播放器和 WebSocket
  -> 本机 Wilbur 127.0.0.1:801/802

Allocator
  -> Worker Agent :9101

客户端
  <==== WebRTC UDP / TURN ====> UE
```

Gateway 不代理 WebRTC 视频和音频，也不是 SFU。

## 2. 机器目录

### Allocator 机器

```text
项目根目录\
├── Allocator\
├── secrets\
│   └── gateway-token.txt
└── stop-all.bat
```

Allocator 机器不需要 WebServers、Windows 游戏构建或 UE。

### 每台 Worker 机器

```text
项目根目录\
├── Allocator\
│   └── config\workers.json       # 可选，用于本机停止脚本
├── Worker\
│   ├── worker01.json
│   └── worker-agent.js
├── Gateway\
│   ├── gateway.js
│   └── gateway.json
├── secrets\
│   └── gateway-token.txt
├── WebServers\
└── <游戏构建目录>\
    └── Windows\
        └── UE_ANDA.exe
```

Worker 机器不需要运行 Allocator，但保留 `Allocator/config/workers.json` 便于根目录 `stop-all.bat` 找到中央 Allocator。

## 3. 运行依赖

所有 Allocator、Worker 和 Gateway 进程需要 Node.js 18 或更高版本，建议 Node.js 22。

WebServers 需要 `node_modules`。如果新克隆后没有：

```powershell
Set-Location WebServers
npm ci
```

Worker 配置可以分别指定：

```json
{
  "windowsDirectory": "<游戏构建目录>",
  "webServersDirectory": "../WebServers",
  "nodeExecutable": "SignallingWebServer/platform_scripts/cmd/node/node.exe",
  "signallingDirectory": "SignallingWebServer",
  "gameExecutable": "UE_ANDA.exe"
}
```

这几个路径可以独立配置，不要求 Windows 和 WebServers 位于同一个目录。

## 4. 部署前需要确定的参数

| 参数 | 示例 | 说明 |
|---|---|---|
| Allocator IP | `192.168.1.188` | 中央调度地址 |
| Worker IP | `192.168.1.189` | 每台 GPU 机器固定 IP |
| Worker ID | `worker02` | 全局唯一 |
| Slot ID | `slot01` | 每台 Worker 内唯一 |
| Client API Key | 长随机值 | 客户端申请 Session |
| Worker Token | 每台不同长随机值 | Allocator 管理 Worker |
| Gateway Token | 所有机器相同 | Gateway 校验 Ticket |

固定命名规则见 [命名规范.md](命名规范.md)。

## 5. 配置 Gateway Token

仓库中的文件：

```text
secrets\gateway-token.txt
```

默认是占位值：

```text
replace-with-a-long-random-gateway-token
```

部署时必须替换。可以运行：

```bat
scripts\initialize-gateway-token.bat
```

脚本只在文件仍为占位值时生成随机 Token；已有自定义 Token 不会被覆盖。

然后把同一个文件复制到：

- Allocator 机器
- 每台 Worker 机器

文件内容必须完全一致。

相关配置：

```text
Allocator\allocator.json -> gatewayTokenFile
Gateway\gateway.json     -> allocatorTokenFile
```

不要把 Gateway Token 发给浏览器。浏览器只使用 Allocator 创建的 Session 和播放器 Ticket。

## 6. 配置中央 Allocator

### 6.1 allocator.json

编辑：

```text
Allocator\allocator.json
```

至少修改：

```json
{
  "listenHost": "0.0.0.0",
  "listenPort": 9200,
  "apiKey": "<client-api-key>",
  "gatewayTokenFile": "../secrets/gateway-token.txt",
  "workersFile": "./config/workers.json"
}
```

正式环境还应限制：

```json
{
  "corsAllowedOrigins": [
    "https://your-web-app.example.com"
  ]
}
```

### 6.2 workers.json

编辑：

```text
Allocator\config\workers.json
```

每台 Worker 配置管理地址、Gateway 地址和 Worker Token：

```json
{
  "workers": [
    {
      "id": "worker01",
      "baseUrl": "http://192.168.1.188:9101",
      "gatewayUrl": "http://192.168.1.188:9300",
      "token": "<worker01-token>"
    },
    {
      "id": "worker02",
      "baseUrl": "http://192.168.1.189:9101",
      "gatewayUrl": "http://192.168.1.189:9300",
      "token": "<worker02-token>"
    }
  ]
}
```

要求：

- `id` 全局唯一，并与 Worker 配置的 `agentId` 一致。
- `baseUrl` 使用 Worker Agent 的 `9101`。
- `gatewayUrl` 使用该 Worker Gateway 的 `9300`。
- 每个 Worker 使用不同的 `token`。
- 地址必须是 Allocator 和客户端实际能够访问的地址。

## 7. 配置每台 Worker

从模板复制：

```powershell
Copy-Item `
  "Worker\worker-template.json" `
  "Worker\worker02.json"
```

编辑 Worker 配置：

```json
{
  "agentId": "worker02",
  "listenHost": "0.0.0.0",
  "listenPort": 9101,
  "authToken": "<worker02-token>",
  "windowsDirectory": "<游戏构建目录>",
  "webServersDirectory": "../WebServers",
  "slots": [
    {
      "id": "slot01",
      "streamerPort": 8001,
      "playerPort": 801,
      "sfuPort": 9001,
      "publicUrl": "http://192.168.1.189:801/"
    },
    {
      "id": "slot02",
      "streamerPort": 8002,
      "playerPort": 802,
      "sfuPort": 9002,
      "publicUrl": "http://192.168.1.189:802/"
    }
  ]
}
```

`authToken` 必须与 Allocator `workers.json` 中同一 Worker 的 `token` 一致。

## 8. 配置 Gateway

默认配置：

```text
Gateway\gateway.json
```

示例：

```json
{
  "listenHost": "0.0.0.0",
  "listenPort": 9300,
  "workerConfigFile": "../Worker/worker01.json",
  "allocatorUrl": "http://192.168.1.188:9200",
  "allocatorTokenFile": "../secrets/gateway-token.txt",
  "upstreamHost": "127.0.0.1",
  "nodeExecutable": "../WebServers/SignallingWebServer/platform_scripts/cmd/node/node.exe"
}
```

需要修改：

- `allocatorUrl`：中央 Allocator 的实际地址。
- `listenPort`：通常所有 Worker 都使用 `9300`。
- `nodeExecutable`：本机 Node 路径。
- HTTPS 部署时增加 `tlsKeyFile` 和 `tlsCertFile`。

通过 `start-worker.bat` 启动时，当前 Worker 配置会自动覆盖 `workerConfigFile`，所以 `worker02` 不需要手工修改这一行。

单独启动 Gateway 时可以显式传入：

```bat
Gateway\start-gateway.bat gateway.json ..\Worker\worker02.json
```

## 9. 启动

### 9.1 启动 Allocator

在中央机器运行：

```bat
Allocator\start-allocator.bat
```

保持窗口运行。

### 9.2 启动 Worker 和 Gateway

在每台 Worker 机器运行：

```bat
Worker\start-worker.bat worker01.json
```

脚本会：

1. 在独立窗口启动 Gateway。
2. 自动把当前 Worker 配置传给 Gateway。
3. 在当前窗口启动 Worker Agent。
4. 等待 Allocator 分配后再启动 Slot 的 Wilbur 和 UE。

只启动 Worker：

```bat
Worker\start-worker.bat worker01.json --no-gateway
```

指定其他 Gateway 配置：

```bat
Worker\start-worker.bat worker02.json ..\Gateway\gateway-worker02.json
```

## 10. 健康检查

### Allocator

```text
http://Allocator-IP:9200/health
```

### Worker Agent

```text
http://Worker-IP:9101/health
```

### Gateway

```text
http://Worker-IP:9300/health
```

正常响应示例：

```json
{
  "ok": true,
  "agentId": "worker01",
  "slots": ["slot01", "slot02"]
}
```

`9300/` 根路径返回 `404` 是正常的，只有 `/health` 和带有效 Ticket 的 `/play/...` 路径可用。

## 11. 网络和防火墙

| 来源 | 目标 | 端口 |
|---|---|---|
| 客户端 | Allocator | TCP `9200` |
| Allocator | Worker Agent | TCP `9101` |
| 客户端 | Gateway | TCP `9300` |
| Gateway | 本机 Wilbur | TCP `127.0.0.1:801/802` |
| 客户端 | UE | WebRTC UDP 或 TURN |

远端不应直接访问 `801/802`、`8001/8002` 和 `9101`。

以管理员身份在每台 Worker 运行：

```powershell
powershell -ExecutionPolicy Bypass -File Gateway\configure-firewall.ps1
```

该脚本放行 `9300`，并阻止远端直接访问当前 Worker 配置中的 `801/802`。

如果使用 HTTPS/WSS，需要准备可信证书，并在 Gateway 配置中启用 TLS。跨公网时还必须配置 TURN。

## 12. 客户端连接

客户端向 Allocator 申请 Session：

```http
POST /api/sessions
X-API-Key: <client-api-key>
Content-Type: application/json

{}
```

Allocator 就绪后返回：

```json
{
  "status": "ready",
  "url": "http://Worker-IP:9300/play/<ticket>/?ss=..."
}
```

客户端直接打开该 `url`。不要自行改成 `801/802`。

完整前端接入见 [客户端连接像素流说明.md](客户端连接像素流说明.md)。

## 13. 停止

停止单个 Gateway：

```bat
Gateway\stop-gateway.bat
```

停止当前 Worker 的全部 Slot，但保留 Worker 和 Gateway：

```bat
Worker\stop-all-slots.bat
```

在 Worker 窗口按 `Ctrl+C` 停止 Worker Agent；在 Gateway 窗口按 `Ctrl+C` 停止 Gateway。

中央机器可运行：

```bat
stop-all.bat
```

它会依次关闭 `workers.json` 中配置的 Gateway、Worker、UE/Wilbur 和 Allocator。

## 14. 常见错误

### Gateway 返回 503

- Allocator 没有启动。
- `allocatorUrl` 错误。
- Allocator `9200` 不可达。
- Gateway Token 文件不存在或无法读取。

### Gateway 返回 403

- Ticket 不属于当前 Session。
- Session 已释放或失败。
- Ticket 被发到了错误的 Worker。
- Worker 配置和 Allocator 分配结果不一致。

### WebSocket 返回 404

- Gateway 仍在运行旧版本。
- URL 没有保留有效的 `/play/<ticket>/` 路径。

### Worker 一直 starting

检查：

```text
Worker\logs\<workerId>\<slotId>\wilbur.log
Worker\logs\<workerId>\<slotId>\ue.log
```

- Windows 游戏路径错误。
- WebServers 或 `node_modules` 不完整。
- Wilbur 端口被占用。
- UE 没有连接到本机 Wilbur。
- GPU、显存或编码资源不足。

### 能打开页面但黑屏

检查 WebSocket 是否连接成功，以及 WebRTC UDP/TURN 是否可达。Gateway 正常不代表媒体网络一定可用。

## 15. 升级流程

1. 先备份实际配置和 `secrets/gateway-token.txt`。
2. 拉取新代码，避免覆盖目标机器上的 IP、Token 和路径配置。
3. 如 `node_modules` 依赖有变化，在 WebServers 执行 `npm ci`。
4. 先重启 Allocator。
5. 再逐台重启 Worker；启动脚本会同步启动 Gateway。
6. 检查 `/health`。
7. 申请测试 Session，确认页面、WebSocket 和视频均可工作。

Allocator 重启会丢失内存中的 Session；升级时应安排维护窗口。
